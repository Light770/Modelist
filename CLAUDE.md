## Commands

Run from the repo root unless noted:

```sh
npm run build:wasm      # wasm-pack → apps/web/src/wasm-pkg (rerun after ANY Rust change used by the web app)
npm run dev             # Astro dev server (needs wasm-pkg built first)
npm run build           # build:wasm + astro build
npm run test:rust       # cargo test --workspace (sim3d drape tests take ~1 min)
cargo test -p modelist-core              # fast loop for 2D kernel work
cd apps/web && npm run test:unit         # esbuild + node --test for src/lib/cad
cd apps/web && npm run check             # astro check (TS type check)
```

Before calling a change done, run the relevant Rust tests, `npm run build:wasm` if the WASM API changed, and `npm run check` if TS changed.

## How the pieces talk

- **Data flow:** the UI calls `kernelClient.ts` → `ModelistSession` methods (WASM). The kernel mutates `PatternProject`, rebuilds from the parametric op timeline, and exposes:
  - `get_ui_snapshot_json()`: the JSON `UiSnapshot` the React chrome consumes (typed in `types.ts`)
  - `get_stroke_coords()` / `get_stroke_meta()` / `get_handle_points()`: typed arrays that Viewport2D draws imperatively
  - `get_sim3d_*()`: typed arrays for the 3D viewport
- **Changing the WASM API** is a 3-place edit: `crates/modelist-wasm/src/lib.rs` → `kernelClient.ts` wrapper → `types.ts` (if the JSON shape changed). Then rebuild wasm-pkg.
- **Parametric model:** fitted blocks (`bodice_sleeve`, `aline_skirt`, `trouser_block`) are built in `blocks.rs`; starter styles (`boxy_tee`, `wide_pleat_trouser`, `barrel_trouser`) in `library/`. Both draft from `BodyMeasurements` + `EaseTable` + variables, then the `ParametricOp` list (timeline, with rollback/suppress/reorder) is replayed. Edits should become ops, not raw geometry mutations, so they survive measurement changes.
- **Template catalog:** `library::TEMPLATE_CATALOG` is the single list of templates (name, category, measurement keys, 3D view region). WASM exposes it as `template_catalog_json()`; the template picker and inspector read it via `apps/web/src/lib/templateCatalog.ts`. Add new templates there instead of hard-coding ids in the UI. New style builders must use `library::sclamp` (never `f64::clamp` with computed bounds, which panics and traps WASM) and pass the library test-suite (`cargo test -p modelist-core library`).
- **IDs:** use `det_id("kind:name")` (UUID v5) for deterministic IDs. Never use random UUIDs for pattern entities.
- **Persistence:** projects are saved as `.modelist.json` via the File System Access API, with IndexedDB autosave (`localFiles.ts`).

## Current state vs. spec (as of 2026-11)

The spec describes the target. These parts of the code currently differ from it, so don't assume the spec is already implemented:
- The WASM kernel runs on the **main thread** (no Web Worker yet); snapshots are JSON strings.
- 2D viewport is **Canvas2D**; 3D viewport is **WebGL2** with a **CPU XPBD** solver in Rust (no WebGPU compute yet).
- The solver runs 12 substeps per frame: anisotropic strain-based membrane (warp/weft/shear), long-range tethers sized from the mesh, per-edge and seam-line stretch limits, quadratic (Bergou) bending calibrated on the Peirce cantilever, inelastic SDF contacts with velocity-level friction, body-point vs triangle contacts. There is **no cloth-to-cloth collision** yet, and lower-body garments get a waistline support until tacks/waistbands exist.
- Seams have no fold angle / turned / layer properties yet (see the 3D overhaul report in memory for the plan).
- Nesting (`nesting.rs`) is an in-house BLF-style implementation. `jagua-rs`/`sparrow` are **not** dependencies. Flag the MPL-2.0 license before adding them.
- Some WASM methods still address edges by `edge_idx: usize` even though the skills prefer `EdgeRef`/UUID references. Prefer UUID-based references in new code.

## Conventions to keep in mind

- All kernel math is `f64` mm; sim3d uses `f32` meters internally (convert at its boundary).
- No geometry math in TypeScript. If the UI needs a measurement or hit test, add a kernel method.
- Never render pattern geometry as React DOM/SVG during interaction. Viewport2D draws from typed arrays in rAF.
- Keep 3D lazy: nothing in `modelist-sim3d` may run unless the 3D Fit Room is open; call `dispose_sim3d` on close.
- New geometric/solver code needs unit tests + `proptest` invariants (see AGENTS.md §3 and spec §10.2).
- **Fabrics are physical:** `FabricSpec` stores N/m, µN·m, g/m², % (see `FABRIC_PROPERTIES` for keys and ranges); old 0-1 slider files are migrated by `FabricSpec::normalized()`. Never add a non-physical fabric knob; extend `FABRIC_PROPERTIES` instead. `fabric_*` formula variables are mirrors of the shell fabric and are read-only.
- **Sim changes need the drape checks:** `cargo test -p modelist-sim3d --release` runs the textile calibration tests and the drape-quality tests (poke-through, creases, waist hold per fabric). Seam gaps and strain alone do not catch crumpling.
- **All UI text goes through i18n:** `const t = useT()` and `t('key')`; add the key to `en.ts` and `fr.ts` (fr is typed, a missing key fails `npm run check`). Kernel catalog names (templates, fabric presets, measurements) are translated by id with `useCatalogT()`. Pattern data typed by users is never translated.
- Studio deep links: `/studio?template=<id>&mode=2d|split|3d&lang=en|fr&tab=<inspector tab>`.
